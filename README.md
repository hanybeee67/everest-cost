# 에베레스트 메뉴 원가 분석 (Everest Cost)

레시피북 v3(87개 메뉴)와 동일한 재료·사용량을 기준으로 만든 **메뉴 원가 분석 시스템**입니다.
식재료 가격과 고정비가 수시로 바뀌는 것을 전제로, **웹(PC·모바일)에서 값을 고치면 즉시 반영되고
그 상태 그대로 엑셀로 내려받을 수 있게** 만들었습니다.

---

## 무엇이 달라졌나

기존 원가 계산서의 문제를 이렇게 정리했습니다.

| 기존 | 새 버전 |
|---|---|
| 카테고리 시트마다 메뉴가 블록으로 반복 · 헤더가 두 종류 섞여 있음 | **한 줄 = 재료 1개** 단일 서식의 `⑤ 레시피 상세` 하나로 통합 |
| 같은 메뉴가 이름만 다르게 중복 (커다이 치킨/커다이치킨, 탄두리치킨(한마리) 2회 등) | 레시피북 기준 **87개 메뉴, 중복 없음** |
| 총원가 수식이 `고정비 − 식재료비` 로 잘못 작성됨 | **총원가 = 식재료원가 + 고정비 배분** 으로 수정 |
| 조회 실패 시 `#N/A`, 0 나눗셈 시 `#DIV/0!` 발생 | 모든 나눗셈·조회를 방어 → **오류값 0건 (자동 검증)** |
| 고정비에 「외상 매입금-식재료비(월 1,700만원)」가 포함되어 식재료 원가와 **이중 계상** | 기본값을 **배분 제외**로 두고 화면에 이유 표시 (한 번에 되돌릴 수 있음) |
| 엑셀만 존재 · 현장에서 수정 불편 | **웹앱(PC/모바일) + 엑셀 내려받기** 병행 |

> 고정비 이중 계상을 바로잡으면서 평균 총원가율이 80.6% → **56.2%** 로 바뀝니다.
> 기존 방식대로 보고 싶으면 `고정비` 화면에서 해당 항목을 「포함」으로 체크하면 됩니다.

## 구성

```
data/dataset.json        원본 데이터 (식재료 118 · 프렙 11 · 메뉴 87 · 고정비 13)
shared/calc.js           원가 계산 엔진 (브라우저/서버 공용, 엑셀 수식과 1:1)
public/                  웹앱 (빌드 과정 없는 순수 HTML/CSS/JS)
server/index.js          Express 서버 (정적 파일 + 저장 API + 엑셀 생성)
tools/extract.py         원본 엑셀 2종 → 원시 JSON
tools/normalize.py       원시 JSON → dataset.json (이름 매칭·검증)
tools/build-xlsx.js      dataset → 엑셀 원가분석서 생성
tools/verify_xlsx.py     생성된 엑셀의 전 수식을 실제 계산해 검증
tools/build-static.js    정적 배포용 파일 모으기 (public/ 만으로 동작하게)
tools/build-single.js    전부 합친 단일 HTML 파일 생성
tools/build-manual.js    화면 캡처를 넣은 사용설명서 HTML 생성
data/template.json       범용 템플릿용 예시 데이터
assets/shots/            설명서에 들어가는 화면 캡처
render.yaml              Render 배포 설정
```

## 실행

```bash
npm install
npm start          # http://localhost:3000
```

원본 엑셀에서 데이터를 다시 뽑거나 엑셀을 다시 만들 때:

```bash
npm run build:data   # 원본 엑셀 → dataset.json   (python3 + openpyxl 필요)
npm run build:xlsx   # dataset.json → 엑셀 파일
npm run build:single # 전부 합친 단일 HTML 파일
npm run verify       # 엑셀 전 수식 검증          (pip install formulas openpyxl)
```

## 범용 템플릿 (회사 이름 없이 누구나 사용)

에베레스트 데이터를 뺀 **빈 템플릿**입니다. 예시 데이터가 들어 있어 바로 사용법을 익힐 수 있습니다.

| 파일 | 내용 |
|---|---|
| `public/downloads/원가분석_템플릿.html` | 템플릿 본체 (약 1MB · 더블클릭하면 실행) |
| `public/downloads/원가분석_템플릿_사용설명서.html` | 화면 캡처 12장이 들어간 사용설명서 (약 750KB) |
| `public/downloads/원가분석_템플릿.xlsx` | 템플릿의 엑셀 버전 |

**들어 있는 예시**

| 예시 | 보여주는 것 |
|---|---|
| 식재료 12종 · 프렙 1종 · 고정비 5항목 | 기본 입력 형태 |
| 치킨 볶음밥 (9,000원) | 식재료 + 프렙을 함께 쓰는 일반적인 메뉴 |
| 감자 크림 수프 (5,000원) | 수율(85%) 처리와 수돗물의 무료 처리 |
| 런치 세트 (12,000원) | 다른 메뉴를 구성품으로 넣는 세트메뉴 |

메뉴를 누르면 재료·사용량·수율·재료비와 **조리법·가니쉬**까지 상세가 열립니다.

```bash
npm run build:template   # 템플릿 HTML 다시 만들기
npm run build:manual     # 사용설명서 다시 만들기 (assets/shots 의 캡처 사용)
npm run build:all        # 엑셀 · 단일파일 · 템플릿 · 설명서 전부
```

### 직접 추가·삭제할 수 있습니다

템플릿으로 쓰려면 값 수정만으로는 부족하므로, 앱에서 항목을 직접 만들고 지울 수 있게 했습니다.

- **식재료** — 추가 · 이름 변경 · 삭제
- **프렙** — 추가 · 삭제, 투입 재료 추가 · 삭제
- **메뉴** — 이름 · 카테고리 · 판매가로 추가, 삭제
- **레시피** — 재료 줄 추가 · 삭제, 구분(식재료/프렙/메뉴/무료) 선택, 조리법 · 가니쉬 입력
- **고정비** — 항목 추가 · 삭제
- **기본 정보** — 회사 이름, 메뉴 카테고리 추가 · 삭제

이름을 바꾸면 그 이름을 참조하던 레시피도 함께 따라 바뀝니다.
지우기 전에는 어디에서 쓰이고 있는지 알려 줍니다.

## 단일 파일 버전 (설치·인터넷 불필요)

`public/downloads/에베레스트_원가분석_단일파일.html` — **약 1.1MB 짜리 HTML 파일 하나**에
데이터·계산엔진·엑셀생성기·화면이 전부 들어 있습니다.

- 파일을 **더블클릭**하면 브라우저에서 바로 열립니다. 설치도, 인터넷도, 서버도 필요 없습니다.
- 외부로 나가는 요청이 **0건**입니다. 매장 와이파이가 끊겨도 그대로 씁니다.
- 웹 버전과 기능이 똑같습니다 — 단가 수정, 원가 재계산, **엑셀 내려받기**까지 전부 됩니다.
- **자동 저장입니다.** 값을 고치면 0.7초 뒤 알아서 저장되고, 저장 시각이 화면에 표시됩니다.
  저장 버튼을 누를 필요가 없고, 그냥 창을 닫아도 값이 남습니다.
- 시크릿(비공개) 모드처럼 브라우저가 저장을 거부하는 상황이면 **빨간 경고 띠**가 뜹니다.
  이때는 값이 남지 않으니 `백업` 으로 파일을 저장해 두세요.
- **`이 값 그대로 파일 저장`** 을 누르면 지금까지 고친 값까지 통째로 담긴 HTML 파일이 만들어집니다.
  그 파일 하나만 다른 PC로 보내면 값 그대로 이어서 쓸 수 있습니다. (아래 참고)

### 다른 PC로 옮기기

HTML 파일만 복사하면 **원본 값**으로 열립니다. 고친 값은 브라우저 안에 있기 때문입니다.
값까지 함께 옮기려면 아래 중 하나를 쓰세요.

**방법 ① 값이 담긴 파일로 저장 (권장 · 파일 1개)**

1. 쓰던 PC에서 **`이 값 그대로 파일 저장`** 클릭 → `에베레스트_원가분석_2026-08-16.html` 생성
2. USB·카톡·메일로 그 파일을 새 PC로 보냄
3. 새 PC에서 더블클릭 → 고친 값 그대로 열림 (「파일에 담겨 온 수정값을 불러왔습니다」 표시)

**방법 ② 백업 JSON (파일 2개 · 값만 따로 관리할 때)**

1. 쓰던 PC에서 `백업` → JSON 저장
2. 새 PC에서 HTML 을 열고 `복원` → 그 JSON 선택

> **어느 값이 쓰이나** — 파일에 담긴 값과 그 PC에 저장된 값 중 **더 최근에 저장된 쪽**이 자동으로 선택됩니다.
> 그래서 새 PC에서는 받아온 파일의 값이, 쓰던 PC에서는 그동안 고친 값이 자연스럽게 이어집니다.

```bash
npm run build:single    # 값이 비어 있는 기본 단일 파일 다시 만들기
```

### 구매자별 파일 발급 (워터마크)

판매할 때 구매자 이름을 파일에 새겨 넣을 수 있습니다. 유출 시 어느 경로인지 추적할 근거가 됩니다.

```bash
node tools/build-single.js "출력파일.html" data/template.json \
  --licensee "한빛식당 김OO" --license-id "EC-2026-0042" --issued "2026-08-17"
```

새겨진 정보가 나타나는 곳:

| 위치 | 내용 |
|---|---|
| 파일 머리말(HTML 주석) | 사용권자·발급번호·발급일 + 무단 배포 경고 |
| 화면 왼쪽 아래 | `사용권자: 한빛식당 김OO · EC-2026-0042` |
| 고정비 → 라이선스 | 발급 정보 전체 |
| 레시피 카드 인쇄물 | 옅은 대각선 워터마크 + 하단 표기 |
| 엑셀 사용안내 시트 | 사용권 정보 |

사용권 정보는 데이터와 분리해 보관하므로 **백업·복원·초기화를 해도 지워지지 않습니다.**

> 다만 이것은 **추적 장치이지 복사 방지 장치가 아닙니다.** HTML 파일이라 마음먹으면 지울 수 있습니다.
> 유출을 확인했을 때 근거로 쓰는 용도로 생각하세요.

## 웹앱

| 화면 | 하는 일 |
|---|---|
| **대시보드** | 평균 원가율·마진율, 판정 현황, 카테고리별 분석, 개선 우선순위 TOP 10 |
| **메뉴** | 87개 메뉴의 판매가·원가·마진. 검색·카테고리·판정 필터, 정렬. 누르면 상세 |
| **메뉴 상세** | 레시피북과 같은 재료·사용량·조리법·가니쉬 + 재료별 원가. 사용량·수율·판매가 수정 |
| **식재료** | 118종의 구매가격·중량 수정 → g당 단가 자동 계산 |
| **프렙** | 소스·반제품 11종의 투입량·완성중량 수정 → g당 원가 자동 계산 |
| **고정비** | 항목별 금액, 배분 포함/제외, 월 추정매출, 판정 기준 |
| **점검** | 판매가 미입력·단가 미입력·추정값 등 확인이 필요한 항목 |

- PC는 사이드바 + 표, 모바일은 하단 탭 + 카드로 자동 전환됩니다.
- 라이트/다크 모드를 지원합니다.
- 수정값은 **서버에 저장**되고 동시에 브라우저에도 백업됩니다.
  서버가 없는 정적 배포에서는 브라우저 저장으로 자동 전환되고, 엑셀도 브라우저에서 직접 만듭니다
  (좌측 하단 표시로 어느 쪽인지 알 수 있습니다).
- **자동 저장** — 값을 고치면 0.7초 뒤 저장되고 저장 시각이 표시됩니다. 저장 버튼은 없습니다.
  브라우저가 저장을 거부하면(시크릿 모드 등) 경고 띠를 띄워 알려 줍니다.
- **되돌리기 / 다시 실행** — 상단 `↶ ↷` 버튼 또는 `Ctrl+Z` / `Ctrl+Shift+Z`.
  최근 30단계까지 되돌아가며, 무엇이 되돌아가는지 이름표로 보여 줍니다.
- **레시피 카드 인쇄** — 메뉴 상세에서 1장, 메뉴 목록에서 화면에 보이는 메뉴 전체를 A4 카드로.
  브라우저 인쇄 대화상자에서 「PDF로 저장」도 됩니다.
- `백업` 으로 JSON 파일을 내려받아 두면 언제든 `복원` 할 수 있습니다.
- `이 값 그대로 파일 저장` 은 **지금 값까지 담은 HTML 파일**을 만들어 줍니다 (다른 PC로 통째로 이동용).
- `엑셀 내려받기` 는 **지금 화면의 값 그대로** 엑셀을 만들어 줍니다.

## 엑셀 원가분석서

`public/downloads/에베레스트_원가분석서.xlsx` (웹에서 최신 값으로 다시 받을 수 있음)

| 시트 | 내용 |
|---|---|
| 📘 사용안내 | 구조·색상 규칙·계산식·주의사항 |
| ⑥ 분석 대시보드 | KPI, 판정 현황, 카테고리 분석, 원가율 상위/하위 10 |
| ④ 메뉴 원가표 | 87개 메뉴 요약 (필터·정렬 가능) |
| ⑤ 레시피 상세 | 재료 한 줄씩 — 사용량·수율만 고치면 됨 |
| ① 식재료 단가 | 구매가격 → g당 단가 |
| ② 프렙 원가 | 반제품 총 재료비 → g당 원가 |
| ③ 고정비 설정 | 고정비·월매출·판정 기준 |
| ⚠ 확인 필요 | 비었거나 추정한 값 목록 |

**노란 셀만 입력**하면 나머지는 전부 수식이 계산합니다.

계산식:

```
g당 단가      = 구매가격 ÷ 총중량(g)
재료비        = 사용량 ÷ 수율 × g당 단가
프렙 g당 원가 = 프렙 총 재료비 ÷ 완성중량(g)
식재료 원가   = 해당 메뉴의 재료비 합계
고정비 배분   = 판매가 × (배분대상 고정비 ÷ 월 추정매출)
총원가        = 식재료 원가 + 고정비 배분
마진          = 판매가 − 총원가
```

### 입력값 처리 (보안)

재료명·메뉴명·조리법처럼 사용자가 넣은 글자는 화면에 그릴 때 전부 이스케이프합니다.
거래처에서 받은 파일을 붙여넣거나, 값이 담긴 파일을 주고받아도
그 안의 태그·스크립트가 실행되지 않고 **글자 그대로** 보입니다.

### 수식 오류가 나지 않도록 한 방법

1. 모든 나눗셈은 `IF(분모>0, …, 0)` 으로 감쌌습니다.
2. 모든 조회(VLOOKUP)는 `IFERROR(…, 0)` 으로 감쌌습니다.
3. **순환참조 차단** — 프렙 안의 프렙, 세트메뉴 안의 단품처럼 같은 시트끼리 서로 참조하는 구조는
   참조 깊이(level)를 계산해 행 블록을 나눠 배치하고, 상위 레벨이 하위 레벨 범위만 조회하게 했습니다.
4. `tools/verify_xlsx.py` 가 생성된 엑셀의 **수식 2,484개를 실제로 계산**해
   오류값이 하나도 없는지, 그리고 웹앱 계산 엔진과 값이 같은지 대조합니다.
   판매가·월매출·중량을 전부 0으로 만든 극단 상황에서도 오류 0건을 확인했습니다.

## Render 배포

### 방식 고르기

| | **[A] Static Site** (추천·무료) | **[B] Web Service** (Node) |
|---|---|---|
| 요금 | 완전 무료 | 무료 가능 / 값 보존은 유료 |
| 서버 잠듦 | 없음 — 항상 바로 열림 | 무료는 15분 후 잠듦 (첫 접속 수십 초) |
| 수정값 저장 | **그 기기 브라우저**에 저장 | **서버**에 저장 → 모든 기기가 같은 값 |
| 기기 간 공유 | 백업 파일(JSON)로 옮김 | 자동 |
| 엑셀 생성 | 브라우저에서 생성 | 서버에서 생성 |

원가표를 사장님 혼자 관리하신다면 **[A] 무료 Static Site로 충분**합니다.
PC에서 고친 단가를 주방 태블릿에서도 그대로 봐야 한다면 [B]가 필요합니다.

### [A] 무료 Static Site 로 올리기

1. Render 대시보드 → **New +** → **Static Site**
2. 이 저장소(`hanybeee67/everest-cost`)를 선택
3. 아래처럼 채웁니다.

   | 항목 | 값 |
   |---|---|
   | Branch | `claude/cost-analysis-redesign-p3vj8z` (병합 후에는 `main`) |
   | Build Command | `npm ci && npm run build:static` |
   | Publish Directory | `public` |

   > **어떤 데이터로 배포할지 고르기**
   > - `npm run build:static` — 에베레스트 실데이터 (메뉴 87개)
   > - `npm run build:demo` — 범용 템플릿 (예시 3개) · **판매용 데모 사이트에 적합**

4. **Create Static Site** → 2~3분 뒤 `https://everest-cost.onrender.com` 같은 주소가 나옵니다.
5. (선택) **Redirects/Rewrites** 에 `Source: /*` → `Destination: /index.html` → `Action: Rewrite` 를 추가하면
   주소를 잘못 입력해도 앱으로 들어옵니다.

> `render.yaml` 이 저장소에 있으므로 **New + → Blueprint** 로 만들면 위 설정이 자동으로 들어갑니다.
> 필요한 파일은 저장소에 이미 들어 있어서, Build Command 를 비워 두고 Publish Directory 만 `public` 으로 해도 동작합니다.

**휴대폰에서 쓰기** — 주소를 열고 `홈 화면에 추가` 하면 앱처럼 전체 화면으로 실행됩니다.

**기기 간 값 옮기기** — PC에서 `백업` → JSON 파일 저장 → 휴대폰으로 보내서 `복원`.

### [B] Web Service 로 올리기 (기기 간 자동 공유)

1. `render.yaml` 에서 `[A]` 블록을 주석 처리하고 `[B]` 블록의 주석을 풉니다.
2. Render → **New +** → **Web Service** → 저장소 선택

   | 항목 | 값 |
   |---|---|
   | Runtime | Node |
   | Build Command | `npm ci --omit=dev` |
   | Start Command | `node server/index.js` |
   | Health Check Path | `/healthz` |

3. **환경변수를 반드시 설정하세요.**

   | 키 | 값 | 설명 |
   |---|---|---|
   | `APP_PASSWORD` | 원하는 비밀번호 | **필수** — 없으면 외부 접속이 전부 차단됩니다 |
   | `SESSION_SECRET` | 아무 긴 문자열 | 없으면 서버 재시작 때마다 로그인이 풀립니다 |
   | `DATASET` | `data/template.json` | (선택) 템플릿으로 서비스할 때 |

### 서버 모드의 접근 제한

원가 자료가 인터넷에 그대로 노출되지 않도록 이렇게 동작합니다.

| 상황 | 동작 |
|---|---|
| `APP_PASSWORD` 설정함 | 로그인 화면 → 비밀번호 확인 후 이용. 세션 30일 유지 |
| `APP_PASSWORD` 없음 | **그 컴퓨터(localhost)에서만** 열림. 외부 접속은 안내 페이지와 함께 차단 |
| `/healthz` | 항상 열림 (Render 헬스체크용) |

- 세션 쿠키는 `HttpOnly` · `SameSite=Lax`, HTTPS 에서는 `Secure` 가 붙습니다.
- 쿠키는 HMAC 으로 서명되어 위조할 수 없고, 만료되면 다시 로그인해야 합니다.
- 비밀번호를 15분 안에 10번 틀리면 그 IP 를 일시 차단합니다.
- 비밀번호 비교는 타이밍 공격을 피하도록 `timingSafeEqual` 을 씁니다.

> 단일 파일 · Static Site 모드는 서버가 없어 이 설정과 무관합니다.

3. 값을 재배포 후에도 보존하려면 **Starter 이상 플랜 + Disk**(mount `/var/data`)를 붙이고
   환경변수 `DATA_DIR=/var/data` 를 넣습니다.
   무료 플랜이면 디스크를 못 붙이므로 재배포 시 서버 저장분이 초기화됩니다
   (브라우저 저장분과 백업 파일은 남습니다).

### 정적 배포용 파일

`npm run build:static` 이 아래를 `public/` 으로 모아 줍니다. 서버 없이 이것만으로 전부 동작합니다.

```
public/dataset.json          원본 데이터
public/calc.js               계산 엔진
public/build-xlsx.js         엑셀 생성기 (브라우저에서도 동작)
public/vendor/exceljs.min.js 엑셀 라이브러리 (내려받기 누를 때만 로드)
public/downloads/…xlsx       엑셀 원가분석서
public/downloads/…단일파일.html  단일 HTML 파일
```

### 세 가지 사용 방식

| | 필요한 것 | 값 저장 | 쓰임새 |
|---|---|---|---|
| **단일 HTML 파일** | 없음 (더블클릭) | 그 브라우저 | 주방 PC·오프라인·USB 배포 |
| **Static Site** | 인터넷 | 그 브라우저 | 휴대폰에서 주소로 접속 |
| **Web Service** | 인터넷 + 서버 | 서버 (기기 공유) | 여러 사람이 같은 값을 볼 때 |

## 확인이 필요한 항목

앱의 **점검** 탭과 엑셀의 **⚠ 확인 필요** 시트에 그대로 정리해 두었습니다.

- **판매가 없음 (8개)** — 탄두리 로티, 치킨/머턴 브리아니, 바스마티 라이스, 지라 라이스, 베지 플로우,
  아마 타마타라 샐러드, 라이따. 기존 원가 계산서에 없던 메뉴라 판매가를 넣어야 원가율이 나옵니다.
- **사용량 추정 (6개)** — 레시피북에 「적당량」으로 적힌 튀김용 식용유. 일단 **20g** 으로 가정했습니다.
- **식재료 단가 미입력 (3개)** — 딸기잼, 청포도, 사프란(레시피에만 있고 DB에 없어 새로 추가).
- **식재료 규격 미입력 (6개)** — 콜라·사이다 등 개당 판매 품목. 중량이 0이라 g당 단가가 0으로 처리됩니다.
- **재료명 매칭** — 레시피북 표기(`닭가슴살 (정육)`)와 DB 표기(`가슴 대한`)가 다른 74종은 매칭표로 연결했습니다.
  화면과 엑셀에 「레시피북 표기」를 같이 보여주니 확인해 보시고, 다르게 잡아야 할 것이 있으면 알려주세요.
- **중복 식재료 정리** — `통마늘`(9,000/7,850원), `스파게티면`(1,150/1,250원)이 DB에 두 번 있어
  나중 행(최신 단가)으로 통합했습니다.
